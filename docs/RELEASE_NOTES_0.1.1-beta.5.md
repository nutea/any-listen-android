# v0.1.1-beta.5 · 重构连接与会话模块

Any Listen Android 非官方客户端的测试版本。v0.1.1-beta.4 修好了「登录成功后闪退」，但用户反馈**播放未缓存歌曲时切换 Wi‑Fi / 移动数据仍会崩溃**。这一版不再在旧的竞态上继续打补丁，而是把服务器连接、会话和重连整体重写成一个单一所有者的状态机。

## 改了什么

- **一个网络观察者。** 之前 `PlaybackService` 和 `AppViewModel` 各自注册 `registerDefaultNetworkCallback`、各自记一份「是否已见过默认网络」，一次 Wi‑Fi ↔ 移动数据切换会同时触发两条互相竞争的重连。现在全进程只有一个 `NetworkMonitor`，回调先归约成稳定的网络身份再对外发布。
- **一个会话所有者。** 新的 `SessionConnectionManager` 用单条协程顺序处理事件，认证、WebSocket 生命周期、退避重连都在它手里。「两个回调各自 restore」「快死的套接字拆掉刚建好的继任者」这类交错在结构上不再可能表达。
- **重连策略变成纯函数。** 所有判断集中在 `ConnectionPlanner`，可以穷举测试：健康会话不会因为系统回调而重建（保留 beta.4 行为）；**网络身份真的变了**才重建（保留 beta.1 行为）；链路只是抖了一下又回到同一网络时**先探活再决定**，不会误伤正在播放的流。
- **IPC 调用不再可能重复恢复协程。** `Message2Call` 改用 `CompletableDeferred`，完成是原子且幂等的；WebSocket 回调全部不抛异常。OkHttp 会把回调里逃出来的异常在自己的线程上重新抛出，那正是 beta.4 之前杀死进程的方式。
- **API 与音频不再互相取消。** 两个 OkHttp 客户端共享连接池和 Cookie，但各有自己的 dispatcher。切换网络时清理旧链路上的 API 请求，不会顺手掐断正在播放的音频流。
- **切歌地址会等重连，而不是直接失败。** 播放未缓存歌曲时若正好在重连，解析会在限定时间内等待新会话并重试一次，而不是立刻报「未连接」让加载失败。
- **后台维护协程不再能杀死进程。** 播放服务与 ViewModel 的长生命周期作用域都装上了 `CoroutineExceptionHandler`：缓存封面、写入播放进度这类后台工作失败只记录日志。
- 顺带修掉两个会长期致命的缺陷：`SingleFlight` 在持有者被取消后会永久卡住（一次超时的会话恢复会让之后所有恢复都失败），以及 `Message2Call` 关闭时对并发收缩的映射取快照可能在 OkHttp 读线程上抛异常。
- 版本号 0.1.1-beta.5（versionCode 8）。未轮换签名密钥。

## 安装

Android 8.0 及以上；当前适配 Any Listen Web Server v0.11.0-beta.1，需要手机可访问的 HTTPS 服务地址。本项目不提供音乐资源或公共服务器。

本版本为 **测试版**。正式包名仍为 `io.github.nutea.anylisten`，与调试版 `.debug` 独立安装。可覆盖安装 v0.1.1-beta.4（同一上传密钥）。

## 如何验证

1. **网络切换（本次重点）**：登录后播放一首**未缓存**的歌曲，确认进度在前进；然后在 Wi‑Fi 与移动数据之间来回切换数次。预期：进程保持存活，短暂缓冲后从当前位置继续播放，**不再闪退**。
2. **飞行模式**：播放未缓存歌曲时开启飞行模式 10 秒再关闭。预期：不崩溃；网络恢复后自动重连并继续播放。
3. **同一 Wi‑Fi 抖动**：播放中短暂关闭再打开路由器所在的 Wi‑Fi。预期：会话在探活通过后原样保留，不会无谓地重建并打断播放。
4. **登录 / 冷启动（不得回归 beta.4）**：清除数据后重新登录；杀进程再打开。预期：进入曲库后进程保持存活。
5. **退出登录**：设置里退出，应回到连接页；重新登录正常。
6. **对照**：网络稳定时正常缓冲不应自行重连。
