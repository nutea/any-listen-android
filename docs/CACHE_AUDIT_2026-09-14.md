# 缓存检查与封面闪烁修复（2026-09-14）

## 范围与结论

检查 ArtworkStore、CacheRevalidator、OfflineAssets、下载校验、PlaybackResolver、StreamingCacheDataSource，以及 ViewModel 和 Compose 图片的触发路径。确实存在文件没有改变、但图片请求被重建，以及重复解析资源地址的路径；不能将此前机制称为完全完善。

## 发现与修改

| 路径 | 原有问题 | 修改 |
| --- | --- | --- |
| 首次封面下载、重新进入页面 | 通知初始值 0 随后变为实际版本；版本直接进入图片请求缓存键，同一个文件可能创建两个请求 | 通知只负责检查，图片键改为文件内容 SHA-256；相同内容保留同一个 ImageRequest |
| 点击播放后封面地址补全 | 清单地址变为接口解析地址，remember(url) 清空已加载图片；即使内容相同也重载 | 地址变化保留旧图，新地址内容相同直接复用；确有变化时用旧图作占位并关闭淡入淡出；file URI 同样按内容处理 |
| 封面地址解析 | 比较清单原始地址与已解析地址，二者不同就绕过 15 分钟间隔 | 单独保存清单来源地址；同时接受界面补全后的地址，避免两种地址交替导致重复解析 |
| 缺失歌词、缺失封面 | 空结果没有与成功文件一样的有效期，播放、重组或切歌会反复请求 | 空结果也保留 15 分钟；期满可重新发现后来添加的资源 |
| 歌词/封面解析失败 | 缺少跨入口退避 | 进程内同曲同资源失败退避 60 秒，显式 force 可重试；正常协程取消不记为失败 |
| 重复音乐库刷新 | 强制校验全部已保留资源，并清空音源解析缓存 | 普通音乐库刷新遵循各资源有效期；不无条件作废全部音源地址 |
| 系统网络能力通知 | 同一网络能力变化反复启动下载恢复和缓存维护 | 只在可用网络改变或失去连接后恢复时触发 |
| 单曲播放失败恢复 | 作废当前曲音源时清空全部歌曲解析缓存、改变其他歌曲流缓存键 | 仅作废失败歌曲，其他曲目继续复用 |
| 相同歌词、封面指针 | 即使文本相同也重写文件 | 相同文本不写盘、不改变时间戳 |
| 离线封面 | 无文件时仍尝试 HTTP | 已知离线时直接读取本地或返回缺失，不发 HTTP |

## 当前刷新规则

- 有缓存先读本地；封面 HTTP 校验、封面地址解析、完整音频校验的间隔为 15 分钟。已知清单封面来源变化可以提前解析新的封面。歌词 sidecar 在联网播放/展示时 stale-while-revalidate：立即返回本地副本，并重新请求 `getMusicLyric`（不传 `isRefresh`，与网页端切歌一致）；约 5 秒内的重复请求合并。全库缓存维护仍按 15 分钟间隔，不会在每一帧请求歌词。
- 封面和音频支持 ETag / Last-Modified 条件 GET。304 不传输完整响应体、不替换文件。200 会逐字节比较，内容相同只更新校验记录，不改资源文件和封面显示键。
- 完整音频后台维护由 PlaybackMaintenance 在播放/缓冲时让出；正常新歌仍通过 Media3 边读边播、同一路字节记录缓存，没有恢复为整曲下载后才起播。
- 部分流缓存与完整离线文件分开；音源解析有效期结束或新会话会重新区分流版本，防止无法验证的旧片段混入新文件。失败单曲不再连带作废其他曲目。
- 正常界面没有强制全库缓存刷新入口；内部 force 仍供明确重试、测试等使用。普通音乐库刷新后，同地址内容更新可能在下一次到期维护时才出现。

## 必须区分的情况

“发起校验”和“替换缓存/重新显示”不同。服务器没有提供有效的 ETag / Last-Modified，或忽略条件请求返回 200 时，客户端在校验到期后仍可能接收完整文件，才能判断内容是否改变；音频也一样。单凭相同 URL、文件长度或标题无法可靠判断服务器是否更换了文件。本次不以这些弱条件跳过必要的内容比较。

首次遇到不同 URL 的图片仍需要取得其内容后才能确认相同，但已显示图片不会为此主动清空。没有缓存且请求失败的图片仍有 UI 层指数重试（2 秒起，最多 30 秒）；这属于首次获取重试，不是已缓存文件的刷新。失败退避记录为进程内状态，重启后可重新尝试。

## 验证

- core:data 52 项单元测试通过，含同内容不重写、304、真实变化、断网/失败回退、缺失结果限频、解析地址不同与界面地址交替仍限频。
- Android 36 模拟器图片测试覆盖首次下载仅一个有效 ImageRequest、相同内容 200、不同 URL / file URI 相同内容复用、无关封面不影响当前图、真实红图变蓝图且保留旧图占位。
- 流式播放与缓存回归使用虚拟音频、真实 ExoPlayer，验证未收完整文件已播放、仅一次流读取、部分文件不发布及单曲作废不影响其他歌曲。
- 这是代码与受控数据测试；没有声称已对用户所有真实歌曲逐首复现或抓取服务端响应。
