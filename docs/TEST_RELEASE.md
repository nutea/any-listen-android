# 测试、性能与发布

## 测试层次

单元：DTO映射、歌曲身份、队列模式、下载状态迁移、资源指纹、错误分类、重试与并发刷新。
集成：HTTP/WSS脱敏fixture、401/超时/重定向、Range 206/200/416、Room事务与迁移、取消下载/原子提交/空间不足。
UI：连接错误、空库、离线库、长文本、大字体、下载按钮与状态一致。
真机：后台播放、蓝牙、来电焦点、系统回收、网络切换、离线冷启动与APK升级。

## 首版验收矩阵

| 场景 | 通过条件 |
|---|---|
| 错误密码/证书错误 | 明确失败，无无限重试，无跳过TLS |
| 会话过期 | 可控恢复或要求登录，离线内容仍可用 |
| 锁屏连续30分钟 | 至少跨3首歌，无异常停止；媒体控制可用 |
| 音频焦点/拔耳机 | 按系统语义暂停或duck，恢复策略一致 |
| Wi-Fi→蜂窝→断网 | 状态清晰，有限重试，遵守仅Wi-Fi下载策略 |
| 飞行模式冷启动 | 可浏览并播放正式下载，拖动正常，不依赖服务器 |
| 下载中断/进程回收 | 已完成数据不损坏，未完成状态可恢复 |
| Range被忽略/源改变 | 不拼接损坏文件，重新获取或报告错误 |
| 磁盘不足/损坏文件 | 无假完成，提示重试/释放空间，不删除其他下载 |
| 删除下载 | 只影响手机副本，远端歌单和原文件不变 |
| 双端歌单修改 | 无静默覆盖；未实现安全合并时明确冲突或限制 |
| 升级覆盖安装 | 会话按策略保留、数据库迁移、下载可用 |

用户真实手机为必测；同时覆盖最低支持API模拟器和一个当前目标API环境。至少验证实际库中的MP3/FLAC；AAC/M4A及其他格式按样本报告支持情况，不泛化。

## 性能预算（目标，非已达成）

用明确设备和冷/热启动条件记录：1万曲目缓存库首屏≤2秒，本地列表搜索p95≤300毫秒，下载歌曲点击到声音p95≤1秒；网络首播单独记录网络条件，不混入本地指标。
测量30分钟后台播放的耗电/内存及基线差异，发现持续增长须修复。M0 获取真实规模后调整预算并说明原因。

## CI与发布

M1 建立构建、单测、Lint。锁定工具链与依赖，CI默认使用fixture，不依赖私人生产服务；无需秘密的PR验证与签名发布分离。
M5 生成签名APK、SHA-256、版本说明、兼容服务器版本和测试报告，发布到私人仓库的Release。签名密钥保存在用户控制的安全位置/受保护CI秘密，仓库只记录操作说明。
APK versionCode 单调递增。演示/调试/正式构建区分；正式包不携带测试密码、私人域名或详细网络日志。
版本回退不承诺数据库向下兼容，必要时导出设置后重装；必须说明卸载会影响应用私有下载。正常升级不得要求清空数据。

## 完成标准

v0.1.0需完成M0–M5、阻断缺陷为零、目标真机闭环通过、已知限制公开记录。未测试项不能写“通过”。仅有APK可构建不能视为验收完成。
